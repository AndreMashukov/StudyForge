# StudyForge

AI-powered study platform: users organize **source documents** in **directories**, apply **rules** to steer generation, and produce **artifacts** (quizzes, flashcards, slide decks, and more) for learning.

Maintained via `/grill-with-docs`. Architectural decisions live in `docs/adr/` (see [002-client-library-paths.md](docs/adr/002-client-library-paths.md) for client Firestore reads/mutations).

## Organization

**Directory**:
A hierarchical folder in a user's library. Owns documents, artifacts, and attached rules. Directories nest via `parentId`; ancestor rules inherit to descendants unless resolution mode says otherwise.
_Avoid_: folder, collection, workspace (when meaning a single directory)

**Library**:
The user's full set of directories and documents — not a separate datastore, but the product concept of "everything I study."
_Avoid_: corpus, datastore

**Document**:
User-owned source material used as input for artifact generation. Ingest paths (file upload, pasted text, URL import) convert existing content to HTML while preserving structure. Prompt generation creates a new learning document and may apply directory rules. Legacy documents may still use markdown storage (`content.md`). Distinct from artifacts: a document is _read_; an artifact is _studied_.
_Avoid_: source doc, file (when meaning study content), content item

**Capture**:
A document created from the mobile app's + sheet (scan, camera, photo, pasted text, or web link), saved into the directory the learner is in or, from outside any directory, the default capture directory.
_Avoid_: upload (alone), import, inbox item

**Default capture directory**:
An ordinary, user-chosen directory where captures land when they are not started inside a directory. Chosen per device; not a special system folder.
_Avoid_: Captures folder, inbox

**Scratch pad**:
On AI Prompt documents, one short open recall question and hidden answer per lesson section (each main `h2`, excluding Glossary and Examples). Stored on the document record, not inside the HTML body. Optional at generation time via the Scratchpad toggle. Each pad can remember prior replaced questions (`avoidedQuestions`) so Generate a different question avoids repeats; Reset clears that list only. Learners use Reveal mode to show the stored answer, or Type mode to submit an answer for a 1 to 10 score and an optional hint when not perfect.
_Avoid_: inline quiz, document Q&A box

**Narration**:
Spoken English audio of a document, generated by a text-to-speech model the first time a learner asks to listen, then kept and replayed. Reads the document's title and prose in order, and short code blocks as **spoken code**; it does not read what cannot be spoken (long code, data blocks, diagrams, images, tables), and a short spoken marker such as "Table." or "Code example." takes the place of each gap. Opaque strings such as UUIDs, hashes, keys and URLs are spoken as a short phrase ("a UUID", "a link to github.com"), never spelled out. A narration keeps the spoken-text rules it was made with until the learner removes it ([ADR 020](docs/adr/020-narration-reads-short-code-blocks.md)). **Scratch pads** are never read. Only a **narratable document** can have one, and a document has at most one. It is part of its document, not an **artifact**: it has no title, is reached only from the document's reader, moves with the document and is deleted with it. Generating a narration costs credits in proportion to the length of the spoken text, and the learner sees that cost before committing; replaying it is free. A narration is kept until the learner removes it, its document is deleted, or its document stops being narratable; it never expires on its own.
_Avoid_: audio version, read-aloud, TTS (in product copy), podcast

**Spoken code**:
A code block a **narration** reads aloud: introduced as "Code example in Python.", one line at a time, with structural symbols dropped, operators said as words and identifiers split into words. Only code up to about 40 seconds of speech is spoken; longer code and data blocks (JSON, YAML, logs, output) keep the "Code example." marker. Spoken code does not make a document more narratable: the **narratable check** still counts code against prose.
_Avoid_: code reading, code TTS, read-out code

**Narratable document**:
A document written in English whose content is mostly prose that makes sense read aloud. Judged when the document's content is first ready and again whenever that content changes, and recorded on the document; an edit can turn a narratable document into a non-narratable one and the reverse. Documents in other languages, or dominated by code, tables, formulas or diagrams, are not narratable; nothing is translated.
_Avoid_: speakable, audio-ready, English document (language alone is not enough)

**Narration part**:
One consecutive stretch of a **narration**, covering a section or a few paragraphs of the document, generated and stored on its own. A narration is its parts in document order; the learner hears them as one continuous recording and can start listening before the later parts are ready. A part that could not be generated is skipped during playback and is not charged; the rest of the narration still plays, and the learner can retry the missing part.
_Avoid_: chunk, segment, clip, track

**Stale narration**:
A **narration** whose document content changed after the audio was generated. Only the **narration parts** whose text changed are discarded; the next listen regenerates those and charges for them alone, and unchanged parts are kept.
_Avoid_: outdated audio, expired narration

**Library search**:
The learner-facing way to find things in their library: directories, documents and artifacts by name, documents by their text, and chats by their title and messages. Covers the whole library, or one directory and its descendants when opened from inside it; there a chat counts when its **Home folder (chat)** is in that tree, and chats without a home folder are left out. Chats are shown in their own section, after a divider, and open in the agent panel. Distinct from the workspace agent's `search_knowledge` over **User knowledge**. See [ADR 019](docs/adr/019-chats-in-library-search.md).
_Avoid_: global search, find, content search (when meaning the whole feature)

**Search record**:
The per-item entry that library search matches against: one for each directory, document, artifact and chat, holding its name and, for a document, its text, or for a chat, its latest reply preview and its message text (newest kept, capped). Kept in step with the item automatically; never edited by the learner.
_Avoid_: search index (when meaning one entry), index row, search document

**Search result**:
One directory, document, artifact or chat returned by library search. A document or chat found by its text shows the matching passage.
_Avoid_: hit (in product copy), match, referenced item

## Generated content

**Artifact**:
Any AI-generated study output stored in a directory: quiz, flashcard set, slide deck, diagram quiz, sequence quiz, or match quiz.
_Avoid_: content, output, generated doc

**Directory item order**:
How a directory's contents are listed, identical on web and mobile (`directory-item-order.ts` in shared types). **Documents**: the learner's drag order when any document has one (ordered documents first), then the rest newest first; new documents land at the top. **Artifacts**: one list of every type, newest first, like a NotebookLM Studio panel. Artifacts have no manual order; a stored `sortOrder` on an artifact is ignored.
_Avoid_: per-type artifact order, A–Z (for documents or artifacts)

**Quiz**:
Multiple-choice questions derived from one or more documents. Generic quiz type — not a diagram quiz or sequence quiz.
_Avoid_: test, assessment (unless user-facing copy)

**Diagram quiz**:
Quiz where each question presents four Mermaid diagrams; the learner picks the diagram that correctly answers the prompt.
_Avoid_: diagram test, mermaid quiz

**Sequence quiz**:
Ordering quiz: the learner arranges shuffled items into the correct sequence.
_Avoid_: ordering quiz, sort quiz

**Flashcard set**:
Front/back cards (with optional descriptions) derived from source documents.
_Avoid_: deck (alone — prefer "flashcard set"), cards

**Language-learning flashcard set**:
A flashcard set whose purpose is vocabulary study in a target language. Distinct from general study flashcard sets; only this kind participates in learned-vocabulary tracking.
_Avoid_: language deck, vocab set, bilingual flashcards

**Target language**:
The language being learned in a language-learning flashcard set, identified by a BCP-47 code and a display name.
_Avoid_: language (alone), locale, L2

**Flashcard term**:
On a language-learning flashcard, the presentation-free target-language word or phrase being learned. Distinct from the card front, which is display-only.
_Avoid_: front (when meaning the vocabulary lemma), lemma, headword

**Learned vocabulary item**:
A user-level normalized **Flashcard term** marked learned from a language-learning flashcard set. Soft-deprioritized when generating new language-learning flashcard sets.
_Avoid_: learned word, mastered card, vocabulary entry

**Slide deck**:
Presentation slides with speaker notes, optionally with generated images.
_Avoid_: presentation, deck (when meaning slides)

## Generation lifecycle

**Generation status**:
Lifecycle on documents and artifacts: `pending` (AI work in flight), `completed` (ready to use), or `failed` (error recorded). Missing status on older records means completed.
_Avoid_: processing state, job status (when meaning the artifact record itself)

**Generation job**:
Durable async work unit for AI generation. Every generation kind runs through a generation job; endpoints create a pending record, enqueue the job, and return immediately. Tracks attempts and status separately from the visible document/artifact record the UI shows as pending.
_Avoid_: task (alone), background job, inline generation

**Pending record**:
A document or artifact Firestore record created before generation finishes, with `generationStatus: pending`, so the UI can show progress without waiting for the LLM.
_Avoid_: stub, placeholder record

**Artifact agent platform**:
Shared server-side LangGraph pipeline that generates an artifact, runs verification gates, self-repairs failures, and only marks the record completed when gates pass. Diagram quiz and flashcards use kind-specific graphs under `artifact-agent-langgraph`.
_Avoid_: agent service, generation pipeline (when meaning this specific platform)

## AI routing

**LLM setup**:
Admin-managed routing profile. Each **generation kind** maps to a **generation route** (provider, model, required modality, workflow). Legacy modality routes (`text`, `vision`, `image`) are being phased out.
_Avoid_: model setting, active provider, preset

**Generation kind**:
Admin-configurable category of routed LLM work — production (quiz, screenshot document), interactive (workspace agent, directory-scoped agent, document question), and sub-steps (slide deck images). Maps to provider, model, and workflow. Keys align with `LlmCapabilityKey` except internal-only aliases (e.g. `diagramQuizAgent` inherits `diagramQuiz`). Operation-centric, not output-centric.
_Avoid_: capability (when meaning admin routing), artifact type (when meaning routing), LLM modality (when meaning routing key), GenerationModelMappingKey (deprecated separate enum)

**Retired generation kind**:
A **generation kind** that no longer exists but still appears on past usage and cost records (for example directory chat and quiz follow-up). Shown as "Retired feature"; its credits and costs still count in totals. Never routable or configurable.
_Avoid_: legacy kind, deprecated kind, unknown kind

**LLM modality**:
Required input/output lane for a generation route: `text`, `vision`, `image`, `embedding`, `decision`, or `speech`. Validates that the chosen provider connection supports the kind — not a routing key. `decision` is served only by OpenRouter connections. `speech` turns text into spoken audio and is what a **narration** is generated through.
_Avoid_: capability (when meaning the routing lane), model type, routing lane

**Decision model**:
A model that answers typed questions (yes/no, choice, score) with probabilities instead of generating text, called through the OpenRouter Decisions API rather than chat completions. Uses the `decision` LLM modality.
_Avoid_: classifier, judge model, Jev (a specific decision model, not the concept)

**Prompt diagram check**:
The `promptDiagramDecision` generation kind: before an AI Prompt document is generated, a decision model judges whether Mermaid diagrams fit the prompt and how many to allow. Unmetered — it reserves no usage credits.
_Avoid_: Jev check, diagram suitability model

**Narratable check**:
The generation kind that decides whether a document is a **narratable document**. A document with too little speakable prose fails without a model being asked; otherwise a decision model judges a sample of its prose. Unmetered. A check that could not be answered leaves the document unjudged, which is not the same as not narratable. An unjudged document, including any created before narration existed, is judged when a learner opens it in the mobile reader.
_Avoid_: Jev check, language detection, narration check (the check is about the document, not the audio)

**LLM setup route** _(legacy)_:
Deprecated modality-keyed route (`routes.text`, `routes.vision`, `routes.image`). Migration backfill source only — removed from admin UI in Task 14; resolver never reads after backfill.
_Avoid_: provider type mapping, global provider selection

**Generation route**:
One generation kind entry inside an LLM setup. Points to a provider connection, model, required LLM modality, and generation workflow. Every LLM call resolves through a generation route — never through legacy modality routes after migration.
_Avoid_: generation mapping, capability route, LLM setup route

**Generation workflow**:
Orchestration policy on a generation route: `direct` (single-pass provider call) or `agentic` (artifact agent platform — draft, gates, repair/refine loops). Most kinds support `direct` only; `diagramQuiz` and `flashcards` require `agentic`. Screenshot `agentic` ships after Task 14.
_Avoid_: sync mode, inline workflow

**Provider connection**:
Admin-managed connection to an LLM provider, including its credential state, supported LLM modalities, provider-specific defaults, and an uploaded **provider model catalog**. Each connection has a stable ID (e.g. `gemini-primary`) and a **provider kind** (`gemini`, `openrouter`, `minimax`, or `together`). Credentials for all provider kinds are stored encrypted in Firestore — not as deployment secrets.
_Avoid_: provider type (when meaning a configured connection), active provider

**Provider model catalog**:
The set of available models uploaded onto a provider connection (from the provider’s list-models response), each with an ID, display label, and supported LLM modalities. Admin uses this catalog to populate model dropdowns for connection defaults and LLM setup routes; models not in the catalog are invalid for save.
_Avoid_: model list (alone), available models (when meaning the connection-owned catalog), model allowlist

**Provider kind**:
The vendor/protocol family of a provider connection (`gemini`, `openrouter`, `minimax`, `together`). Distinct from a connection ID: multiple connections could share a kind in the future.
_Avoid_: provider type (prefer **provider kind** on connection documents)

**Generation model usage**:
Structured audit entry recording which generation route handled an LLM call (kind, workflow, provider connection, model, setup). Stored on completed records alongside the compact `generationModel` display label.
_Avoid_: model label (when meaning full audit trail)

## Rules

**Rule**:
User-authored markdown instruction that steers AI behavior for a specific operation (quiz generation, scraping, flashcard descriptions, etc.). Rules attach to directories and/or are selected explicitly at generation time.
**Product copy: Prompt.** Learners see rules as "prompts" in the web app, the mobile app and workspace agent replies. Code, types, Firestore (`rules`), URLs (`/rules`), agent tool names, the External API and the admin app (**rule blueprints**) keep "rule". See [ADR 014](docs/adr/014-rules-called-prompts-in-ui.md).
_Avoid_: prompt template, instruction (alone), policy; "rule" in learner-facing copy

**Agent prompt**:
A **rule** whose applicability is `agent`: a saved request for the **workspace agent** (for example "recap the quizzes I took today, with a poem and a diagram for each"), run by typing "/" in the agent composer and picking it; text typed after it adds detail for that run. Global: never attached to a directory, so **always apply** does not concern it. Exclusive: a rule that applies to `agent` applies to nothing else. Other rules steer an operation; an agent prompt is the request itself, and it runs with the same safeguards and cost as the same text typed by hand. The learner can ask the agent to save the current request as one. See [ADR 017](docs/adr/017-agent-prompts-are-rules.md).
_Avoid_: skill, slash command (when meaning the saved rule), macro

**Suggested agent prompt**:
A published **rule blueprint** with the `agent` applicability. Every learner sees it in the "/" menu under their own **agent prompts** and can run it without copying; it always runs the currently published text. "Save a copy" makes an editable **agent prompt** that replaces it in that learner's menu.
_Avoid_: built-in command, system prompt, default prompt

**Additional instructions**:
One-off free text typed into the Create Artifact modal for a single generation. Not saved, not attached to a directory, and not a **rule** (so not a "prompt" in product copy).
_Avoid_: additional prompt, custom prompt

**Rule applicability**:
Which operation types a rule may apply to (e.g. `quiz`, `diagram_quiz`, `flashcard_desc`). A rule can apply to multiple operations. The `prompt` applicability (AI Prompt document generation) is labelled **AI Document** in product copy, so a learner never reads "prompt applies to Prompt". The `agent` applicability ("Workspace agent" in product copy) makes the rule an **agent prompt** and is exclusive. `followup` and `chat` are retired: older rules may still carry them, but nothing applies them.
_Avoid_: rule type, rule category, follow-up rule, chat rule

**Rule resolution mode**:
How explicitly selected rules combine with the directory's default rules (see **always apply**): `inherit` (defaults only), `inherit-plus-explicit` (defaults, then the selected ones), or `explicit-only` (only the selected ones).
_Avoid_: rule merge mode, inheritance setting

**Always apply**:
Whether a rule applies by default in a folder. A rule attached to a folder or an ancestor applies by default there. Any folder can switch it off or back on; that affects the folder itself only, not its subfolders (stored on the rule as `alwaysApplyOffDirectoryIds`). A folder's **default rules** are the ones that apply by default: they start ticked in the prompt pickers, and they are what generation applies when nothing was picked (mobile one-tap quiz and flashcards, documents the workspace agent creates, photo and scan captures). Every tick in a picker, and the toggle on the folder's Prompts tab, saves the folder's defaults at once. Pasted text, links and files are never rewritten by rules. See [ADR 016](docs/adr/016-folder-default-prompts-cascade.md) and [ADR 018](docs/adr/018-prompt-picker-ticks-save-per-folder.md).
_Avoid_: default rule (for one rule; say the rule is on or off by default), auto-select rule, global always apply

## Learning & chat

**Workspace agent**:
Tool-capable AgentPanel over the user's full library (`scope: workspace`). Runs a plan-execute LangGraph: planner, executor, replan loop, then a final reply. Creating a document enqueues **documentFromPrompt**, which applies the target directory's default rules (see **always apply**). Retrieves **Platform agent knowledge** into the planner prompt; searches **User knowledge** with `search_knowledge`.
_Avoid_: global agent (alone), workspace chat, ADK workspace agent

**Directory-scoped agent**:
Same plan-execute LangGraph as the workspace agent, but tools are limited to one directory tree and its descendants (`scope: directory`). No client starts new directory-scoped chats any more: mobile folder chats are workspace-scoped with the folder as context. Older mobile threads keep `scope: directory`.
_Avoid_: folder agent, scoped workspace agent, directory chat

**Home folder (chat)**:
The directory a chat was started in: its first message's context was that directory (web folder page, mobile folder composer, mobile Assistant home with a folder picked). Stored as `homeDirectoryId` on the thread, set once at creation and never changed; document chats have none. Unrelated to scope: a chat with a home folder is still a **workspace agent** chat. A directory's Chats tab lists the threads whose home folder it is, newest message first. Threads from before the field were backfilled from `directoryId` on directory-scoped threads.
_Avoid_: chat directory, scoped chat (when meaning home folder)

**Agent turn**:
One user message and the agent's work to answer it (one run of the plan-execute graph). It runs in the `runAgentTurnTask` Cloud Task, not in the client's request, so closing the panel, leaving the screen or backgrounding the app never stops it. Clients follow it through its **agent turn doc** and re-attach when they come back. Durable chat history stays on the StudyForge agent thread.
_Avoid_: agent session, agent request, stream (when meaning the turn itself)

**Agent turn doc**:
Client-readable Firestore record of one **agent turn** (`agentThreads/{threadId}/turns/{turnId}`): status, live status line, reply text so far, actions and cards, then the terminal outcome. Written only by Functions; 7-day TTL. Distinct from the thread's messages (the durable transcript) and from the **workspace agent checkpoint** (graph state).
_Avoid_: turn status (when meaning the whole record), job

**Active turn**:
The **agent turn** a thread is still answering (`activeTurnId` on the thread). A thread has at most one; sending another message while it runs is refused.
_Avoid_: current request, open stream

**Stop (agent turn)**:
The user's explicit cancel of an **agent turn**. The only thing that ends a turn early on purpose; work already started (for example a queued document) keeps going, and the reply so far is kept.
_Avoid_: abort (in product copy), close

**Workspace agent checkpoint**:
Transient LangGraph checkpoint for one **agent turn**, used by a task retry to resume where the failed attempt stopped. Stored under the user with a 7-day TTL. Not the StudyForge agent thread and not the **agent turn doc**.
_Avoid_: agent thread (when meaning checkpoint data), ADK session

**Platform agent knowledge**:
Admin-published operational policy for the workspace agent (credits, allowed artifacts, clarify-before-generate). Distinct from the user's library notes.
_Avoid_: RAG (alone), knowledge base (alone), system prompt policy

**Platform knowledge chunk**:
Embedded slice of a published **Platform agent knowledge** document, retrieved into the planner prompt.
_Avoid_: RAG chunk, embedding (when meaning the policy text)

**User knowledge**:
User-owned notes searchable with `search_knowledge`. Distinct from **Platform agent knowledge**.
_Avoid_: RAG (alone), personal knowledge base, memory (when meaning note search)

**Referenced item**:
A directory, document, or artifact that the workspace agent or directory-scoped agent surfaced through its tools during a turn, shown to the learner as a tappable card. Comes from tool results, never from IDs written in the reply text.
_Avoid_: citation, **search result** (that is a row returned by **library search**)

## Learning telemetry & statistics

**Quiz attempt**:
A durable record of one visit to a quiz artifact (quiz, diagram quiz, sequence quiz, or match quiz). Written when the learner finishes or leaves after answering at least one question. Stores only answered questions; unanswered questions are not counted as misses.
_Avoid_: session (when meaning this Firestore record), quiz result (alone)

**Statistics failure group**:
One row in Statistics for a single missed quiz question or failed flashcard, grouped by quiz type + quiz + question index, or by flashcard set + card. Shows the latest miss and how many times it was failed in the loaded history.
_Avoid_: failure record (alone), miss entry

**Hidden statistics failure**:
A user choice to remove a **statistics failure group** from Statistics lists and from accuracy / fail counts. The underlying **quiz attempt** or **flashcard study session** is kept; only the grouped view is suppressed.
_Avoid_: deleted failure, dismissed miss

**Flashcard study session**:
A durable record of one visit to a flashcard set. Written when the learner leaves or finishes a turn after marking at least one card. Failed cards in that session appear in Statistics; unmarked cards are omitted.
_Avoid_: flashcard attempt, deck session

## Plans and billing

**Usage limits setup**:
Named catalog entry for monthly credits, storage, daily slide-deck caps, and per-feature access. Users experience it as their plan tier.
_Avoid_: plan doc (when meaning this catalog row), quota profile

**User group**:
Assignment bucket that links a user to one usage limits setup and one LLM setup.
_Avoid_: tier (alone), role, account type

**Default registration group**:
The single user group assigned to new verified users before they subscribe to a paid plan (Free).
_Avoid_: signup group, free tier group

**Subscription**:
Stripe monthly recurring charge mapped to a paid usage limits setup via `stripePriceId`. Checkout creates the subscription; webhooks keep the user's group in sync.
_Avoid_: plan payment (alone), Stripe plan (when meaning the StudyForge setup)

**Pay-as-you-go**:
Optional overage billing after included monthly credits are exhausted, billed separately from the subscription with a monthly cap.
_Avoid_: PAYG (in user-facing copy), usage billing (when meaning overage only)

## Release

**Release plan**:
The checked set of actions for one push to production: which deploy targets ship, which functions are deployed, and which **Release operations** run. An LLM proposes it from deterministic change facts. Code rejects unknown names and adds back any function the import graph marks as affected.
_Avoid_: deploy script, AI deploy, pipeline decision

**Release operation**:
A named, allowlisted step beyond shipping code, such as deploying Firestore indexes, granting a function's IAM, or running a migration script. A **Release plan** can only pick from the allowlist and never contains free-form commands.
_Avoid_: post-deploy hook, custom step

**Migration ledger**:
The production record of which migration scripts have been applied, one entry per script. A script with an entry is never picked by a **Release plan** again. Scripts that existed before the ledger are seeded as applied.
_Avoid_: migration history, applied list

**Release phase**:
The point in a release where a migration script runs, declared by the script itself. It is either before functions deploy (the new code needs the migrated data) or after (the new code handles both shapes). A script that declares no phase never runs automatically.
_Avoid_: migration order, pre/post hook

## Relationships

- A **Directory** contains **Documents** and **Artifacts**
- **Artifacts** are generated from one or more **Documents** in the same directory
- **Rules** attach to **Directories** and inherit down the tree
- A **Rule** attached to a **Directory** **always applies** there and in its subdirectories, unless a directory on the way switched it off
- A **Generation job** drives async completion of every **Pending record** created by AI generation
- A **LLM setup** has one **generation route** per **generation kind**
- A **generation route** points to one **Provider connection** and declares a required **LLM modality**
- Every routed LLM call resolves a **generation route** by **generation kind** (full resolver coverage; legacy modality routes are migration-only)
- A **Language-learning flashcard set** has one **Target language**
- Checking a card in a **Language-learning flashcard set** may create a **Learned vocabulary item** for that user and **Target language**
- A **Quiz attempt** or **Flashcard study session** feeds **Statistics failure groups**; **Hidden statistics failures** filter what Statistics shows without deleting raw telemetry
- A **Capture** creates a **Document** in the current **Directory** or the **Default capture directory**
- A **Narratable check** decides whether a **Document** is a **Narratable document**; a narratable document has at most one **Narration**, made of **Narration parts** in document order
- An **agent turn** may return **Referenced items** alongside its reply
- An agent thread has at most one **Home folder**; a **Directory** lists the chats whose home folder it is
- Every **Directory**, **Document**, **Artifact** and chat (agent thread) has one **Search record**; **Library search** returns **Search results** drawn from them
- An agent thread has many **agent turns** and at most one **active turn**; every turn that ends writes exactly one assistant message
- **Platform agent knowledge** is retrieved as **Platform knowledge chunks** into the workspace-agent planner prompt; **User knowledge** is searched separately with `search_knowledge`

## Flagged ambiguities

- **Document vs artifact** — both can be AI-generated; "document" means source material, "artifact" means study output. Prompt-generated HTML is a document, not an artifact.
- **Narration vs artifact** — a narration is AI-generated from a document but is not an artifact. It is not listed in a directory, has no **search record**, and does not appear among the things generated from a document to study.
- **Quiz** — used generically in some API paths; prefer the specific kind (diagram quiz, sequence quiz) when the distinction matters.
- **Record vs job** — the user-visible Firestore entity (document/artifact) vs the `GenerationJob` tracking async work; don't conflate their status fields.
- **"Due"** — StudyForge has no spaced-repetition schedule, so nothing is "due". Say "missed" for cards and questions drawn from **statistics failure groups**.
- **"Assistant"** — in mobile copy, means the **workspace agent** or **directory-scoped agent**.
- **"Chat"** — means a conversation with the **workspace agent** or **directory-scoped agent**. StudyForge no longer has directory chat; don't name a third conversational surface "chat". A folder's **Chats** tab lists chats by **Home folder**, not by scope.
- **"Explanation"** — quiz, diagram quiz, sequence quiz and match quiz questions have none; the learner sees only whether the answer was right. A flashcard's explanation is part of the card's back, not answer feedback.
- **"Prompt"** — in learner-facing copy, means a **rule**. In code and the domain model it also appears in **AI Prompt** documents (`documentFromPrompt`, the Create Document source) and in LLM prompts; those are not rules. **Additional instructions** are not rules either.
- **"Search"** — alone, means **library search**. The agent looking through **User knowledge** is knowledge search, and what it surfaces are **Referenced items**, not **search results**.
- **"Turn"** — means an **agent turn** in agent code and docs. The **flashcard study session** definition also says "turn" for one visit to a set; that is unrelated.
